Quick reference

Fencing tokens

An increasing acquisition number lets the protected resource reject delayed work from an older lock holder.

Five required invariants

  1. Each successful acquisition atomically receives a token greater than every earlier token for that resource.
  2. Every protected operation carries its acquisition’s token.
  3. The resource remembers the newest token it has accepted.
  4. The resource atomically rejects an older token while applying the protected operation.
  5. The token counter survives release, expiry, and lock-table cleanup.

A client-side token check is not fencing. The resource receiving the operation must enforce it. Checking then writing in separate operations is also insufficient.

Fencing orders different acquisitions. Duplicate requests carrying the same token still require an idempotency design where duplicate effects matter.

When the resource cannot check tokens

StrategyUse whenBoundary
Resource-side compare-and-swapThe resource supports an expected-version precondition, such as S3 If-Match.Every writer must use the precondition; this prevents overwriting a changed version rather than ordering arbitrary tokens.
Atomic transactionThe data and highest token/version can live in one transactional store.The check and protected write must commit together; DynamoDB transactions are Regional.
Single-writer gatewayAll operations can pass through one sequencing component.No bypass paths; gateway failover must preserve ordering and prevent two active writers.
Idempotent operationsRepeating the same logical operation can be made harmless.Deduplication handles repeated effects, not arbitrary stale or conflicting writes.
Best-effort lockThe lock exists only to save duplicated effort or cost.Unsuitable when overlap can corrupt state or violate an invariant.

Timing changes are only mitigations. Longer leases, more heartbeats, and Chubby-style lock-delay can reduce stale-request probability, but cannot establish correctness under arbitrary pauses or delays. Changing lock stores alone also does not remove the resource-enforcement boundary.
