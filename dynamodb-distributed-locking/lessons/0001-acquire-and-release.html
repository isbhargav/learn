Your win

You will be able to implement the acquisition and release core, including the ownership guard that prevents a stale holder from deleting a successor’s lock.

One item represents one lock

Use LockID as the partition key. Store an OwnerID unique to this acquisition and an ExpiresAt lease deadline in Unix epoch seconds.

The AWS locking guide makes acquisition a single conditional update: the item must be absent or expired. DynamoDB evaluates that condition against the item being written, so competing callers cannot both pass it.

import time
import uuid
from boto3.dynamodb.conditions import Attr

def acquire_lock(table, resource_name, ttl_seconds):
    owner_id = str(uuid.uuid4())
    now = int(time.time())
    try:
        table.update_item(
            Key={"LockID": resource_name},
            UpdateExpression=(
                "SET OwnerID = :owner, ExpiresAt = :expiry"
            ),
            ConditionExpression=(
                Attr("LockID").not_exists()
                | Attr("ExpiresAt").lt(now)
            ),
            ExpressionAttributeValues={
                ":owner": owner_id,
                ":expiry": now + ttl_seconds,
            },
        )
        return owner_id
    except table.meta.client.exceptions.ConditionalCheckFailedException:
        return None

A returned token means “I acquired this lease.” None means “someone else currently holds it.” Other exceptions should propagate rather than being mistaken for contention.

Release is a guarded delete

An unconditional DeleteItem is unsafe. Your lease may expire, another caller may acquire, and then your old request could delete the new caller’s lock. The owner check turns release into a compare-and-delete operation.

def release_lock(table, resource_name, owner_id):
    try:
        table.delete_item(
            Key={"LockID": resource_name},
            ConditionExpression=Attr("OwnerID").eq(owner_id),
        )
        return True
    except table.meta.client.exceptions.ConditionalCheckFailedException:
        return False

Call release in finally only when acquisition succeeded. A failed release after lease expiry is expected: it means this token no longer owns the item.
